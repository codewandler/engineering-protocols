## Commands

### `SendEmail`

`billing.email.SendEmail`.

It takes:

- `recipient` — `billing.email.EmailAddress`
- `template` — `billing.email.TemplateId`

It has two outcomes.

**`sent`** — The default branch, taken when no other outcome's condition matched. No entity in this specification changes. It emits `billing.email.EmailSent`. A test reaches it by constructing an input that satisfies no other outcome's condition.

**`failed`** — Decided outside the input: the provider rejects the recipient address. No predicate over the input reaches this branch, and saying `when: false` instead would have claimed it is unreachable, which is a different and false statement. No entity in this specification changes. It reports `billing.email.Undeliverable`. It emits nothing. A test reaches it by injecting the declared fault, because no input can.

## Events

### `DeliveryEscalated`

`billing.email.DeliveryEscalated`, shown to a person as "Delivery escalated".

It carries:

- `recipient` — `billing.email.EmailAddress`
- `template` — `billing.email.TemplateId`

Emitted when binding `notify-on-invoice-created` escalates: `billing.email.SendEmail` failed and a person was told.

## Errors

### `Undeliverable`

The address was rejected by the provider.

It carries nothing beyond its name, so a caller can tell what went wrong and not which value caused it.

Reported by `billing.email.SendEmail` on its `failed` outcome.
